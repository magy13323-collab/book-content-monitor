# Book Content Monitor

Python-проект для обработки книжного каталога в Excel и проверки признаков размещения книг на веб-страницах. Программа сопоставляет название и автора с локальными областями HTML или основной идентичностью PDF, проверяет принадлежащие произведению признаки контента и сохраняет решение с объяснением.

Результат каждой проверки — статус **0, 1 или 2**, код причины и доказательства. Все демонстрационные данные вымышлены; пример запускается на локальных HTML/PDF-фикстурах без обращения к внешним сайтам.

## Основные возможности

- Нормализация текста и URL с сохранением исходных значений и номера строки Excel.
- Выявление полных дублей, повторяющихся URL, вариантов авторства и неоднозначных записей. Спорные кандидаты отмечаются для проверки.
- Ограниченная HTTP-загрузка, извлечение HTML и текстовых PDF, обработка редиректов и относительных ссылок с `<base href>`.
- Сопоставление названия, автора и номера тома с каталогом. Учитываются JSON-LD и самостоятельные книжные карточки, в том числе вложенные и расположенные вне `main`.
- Проверка принадлежности контента: ссылки на EPUB и другие книжные файлы, чтение, текст произведения, аудио и явно обозначенный состав сборника. Рекомендации и автор публикации рассматриваются отдельно от книги.
- Дополнительная проверка JavaScript и вычисленных CSS-стилей через Playwright/Chromium при обоснованной необходимости.
- Экспорт в XLSX и JSONL с причинами, локаторами областей, признаками контента и сведениями о HTTP/браузерной проверке.

| Статус | Значение |
|---|---|
| **1** | Название и автор совпали; найден доступный признак контента, связанный с этой книгой. |
| **0** | Проверка завершилась определённым отрицательным результатом: например, обнаружена другая книга, страница отсутствует или признаки размещения не найдены. |
| **2** | Данных недостаточно для уверенного решения: недоступность, незавершённая JS-загрузка, конфликт идентичности, неподтверждённая видимость или принадлежность контента. |

Статус 1 показывает признаки размещения. Он не доказывает полноту файла или нарушение авторских прав. Аудиоверсия того же произведения учитывается как размещение; отличия от формата каталога отражаются в `observed_formats` и `format_difference`.

## Архитектура

```text
Excel
├─ Лист 1 → нормализация и дедупликация → кандидаты и спорные записи → Excel
└─ Лист 2 → URL и каталог → нормализация ключей → HTTP
   → HTML / PDF / Playwright при необходимости
   → сопоставление книги и принадлежащих ей признаков контента
   → статусы 0 / 1 / 2 + причины и доказательства → Excel / JSONL
```

`part1.py` обрабатывает первый лист, `part2.py` управляет проверкой URL второго листа. Второй этап не требует предварительного запуска первого. `pages.py` отвечает за загрузку и извлечение признаков, `browser.py` — за ограниченную браузерную проверку; результат браузера проходит тот же механизм сопоставления.

## Технологический стек

| Инструмент | Назначение |
|---|---|
| Python 3.10+ / 3.12+ | Базовый HTTP-режим / необязательный браузерный режим |
| openpyxl | Чтение и экспорт Excel |
| requests | HTTP-запросы |
| Beautiful Soup | Разбор HTML |
| pypdf | Извлечение текста и метаданных PDF |
| Playwright + Chromium/Edge | Необязательное выполнение JavaScript и проверка CSS-видимости |
| pytest | Офлайн-тесты и регрессионные сценарии |

Версии закреплены в [requirements.txt](requirements.txt) и [requirements-browser.txt](requirements-browser.txt). Для базового режима достаточно **Python 3.10+**. Для `requirements-browser.txt` нужен **Python 3.12+**: закреплённый `pyee==14.0.0` требует 3.12. Он совместим с Playwright 1.64.0, который допускает `pyee>=13,<15`; закрепления сохранены. Проверено на Windows с Python 3.14.3; другие платформы отдельно не проверялись.

## Быстрый запуск офлайн-демо

Команды ниже рассчитаны на PowerShell и выполняются из корня репозитория. Для новой среды:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Установка пакетов требует сети. Само демо после установки работает без сети и без браузера:

```powershell
.\.venv\Scripts\python.exe -B examples/run_demo.py --browser off --output-dir results/demo-http
```

[Учебный Excel](examples/synthetic_input.xlsx) содержит два листа:

- `Records`: **18 записей**, включая полный дубль, повторяющиеся URL, возможное зеркало, разные форматы, варианты имени автора, номера томов и пропущенные поля.
- `Catalog`: **7 сценариев** проверки одной вымышленной книги по разным локальным документам.

Демо использует настоящие точки входа `part1.py` и `part2.py`. HTTP-ответы подставляются из `examples/fixtures/`, а неожиданные HTTP-запросы запрещены. Адреса `library.example` служат идентификаторами фикстур. Не запускайте обычный сетевой CLI на этих адресах для воспроизведения демо.

| Фикстура | Сценарий | HTTP-only | С Chromium |
|---|---|---|---|
| `own.html` | Карточка книги со своей EPUB-ссылкой | 1 | 1 |
| `foreign.html` | Карточка другой книги | 0 | 0 |
| `uncertain.html` | Содержимое остаётся в состоянии загрузки | 2 | 2 |
| `own.pdf` | Титул, метаданные и основной текст своей книги | 1 | 1 |
| `foreign.pdf` | PDF другого произведения | 0 | 0 |
| `review.pdf` | PDF с явно указанной ролью рецензии | 2 | 2 |
| `dynamic.html` | Карточка с EPUB появляется после JavaScript | 2 | 1 |

«С Chromium» означает режим `auto`: браузер запускается только при необходимости, статические HTML/PDF могут быть проверены через HTTP. Для браузерного примера используйте окружение на **Python 3.12+**, затем установите дополнительные пакеты и движок:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-browser.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -B examples/run_demo.py --browser auto --output-dir results/demo-browser
```

Установка движка требует сети; браузерное демо использует только перехватываемые локальные ответы. В нём задан таймаут 7 секунд на браузерную проверку.

Каждый запуск создаёт `part1_processed.xlsx`, `part2_results.xlsx` и `part2_results.jsonl` в выбранном каталоге. Повторный запуск перезаписывает эти файлы. Без `--output-dir` демо пишет в `examples/output/`. В этом каталоге уже сохранены три [учебных результата HTTP-only](examples/output/), полученные программой. Локальные результаты в `results/` исключены из Git.

## Пример JSON-результата

Сокращённая первая запись из [examples/output/part2_results.jsonl](examples/output/part2_results.jsonl). Значения взяты из сохранённого демо; остальные диагностические поля опущены.

```json
{
  "url": "https://library.example/own.html",
  "http_status": 200,
  "method": "HTTP",
  "expected_title": "DemoBook Amber 101",
  "expected_author": "Mira Placeholder",
  "status": 1,
  "reason_code": "placement_signs",
  "content_signals": [
    {
      "kind": "file_link",
      "format": "ebook",
      "url": "https://library.example/files/amber.epub",
      "detail": "Ссылка на файл epub: Download EPUB",
      "binding": "bound",
      "scope_title": "DemoBook Amber 101",
      "document_url": "https://library.example/own.html",
      "raw_resource": "/files/amber.epub",
      "semantic_role": "book",
      "scope_authors": [
        "Mira Placeholder"
      ],
      "scope_locator": "article",
      "element_locator": "a",
      "binding_reason": "Область с заголовком проверяемой книги; вложенные области проверены."
    }
  ]
}
```

`binding: "bound"` означает, что ссылка отнесена к локальной области совпавшей книги. `method: "HTTP"` в офлайн-демо обозначает HTTP-ветвь обработки подставленного ответа, а не внешний сетевой запрос. Полный результат также содержит извлечённые метаданные, сведения о попытках проверки и исходной строке Excel.

## Собственный Excel и режимы HTTP/Chromium

Создайте `my_books.xlsx` с двумя листами. Их имена произвольны, важен порядок. Для совместимости используйте первые шесть колонок в следующем порядке:

| Колонка | Содержание |
|---|---|
| `Правообладатель` | Исходное значение для учёта и проверки конфликтов |
| `Автор` | Автор книги |
| `Название` | Название с номером тома, если он есть |
| `Тип контента` | Например, `ebook` или `audio` |
| `url` | Абсолютный HTTP(S)-адрес |
| `Сайт` | Хост источника |

Первый лист содержит записи для нормализации и дедупликации. Второй — URL и ожидаемую книгу каждой строки; автор и название обязательны. Образец расположения колонок есть в `examples/synthetic_input.xlsx`.

Локальная обработка первого листа:

```powershell
.\.venv\Scripts\python.exe -B part1.py --input my_books.xlsx --output results/my-books/part1_processed.xlsx
```

Выходные листы: `Normalized`, `Duplicates`, `Books`, `Review`. Исходные значения сохраняются, спорные авторы и издания автоматически не объединяются.

Следующие команды выполняют **реальные сетевые запросы** к URL вашего файла. HTTP-only режим:

```powershell
.\.venv\Scripts\python.exe -B part2.py --input my_books.xlsx --browser off --output-dir results/my-books/http
```

HTTP-only не исполняет JavaScript и не вычисляет CSS. При существенной неопределённости результат остаётся 2, даже если название или ссылка присутствуют в HTML.

Режим с браузерной проверкой при необходимости:

```powershell
.\.venv\Scripts\python.exe -B part2.py --input my_books.xlsx --browser auto --output-dir results/my-books/browser
```

`auto` включён по умолчанию. Он учитывает незавершённую загрузку целевой книги, динамические действия, неопределённую CSS-видимость и некоторые ответы ограничения доступа. Готовая чужая карточка не завершает ожидание целевой. На URL допускается одна браузерная попытка; стандартный таймаут — 25 секунд, параметр `--browser-timeout` меняет его.

Автопоиск выбирает установленный Chromium Playwright, затем Edge в Windows. Параметр `--browser-channel` принимает `auto`, `chromium`, `msedge` или `chrome`; `--browser-executable` позволяет указать путь к движку. Если пакет или движок недоступен, URL, которому нужен браузер, получает 2 с причиной `browser_unavailable`. Программа сама не устанавливает браузеры.

Вместо Excel второй CLI также принимает `--catalog` с JSON-массивом книг и `--urls` с текстовым списком URL. Эта пара используется отдельно от `--input`. Поля книги: обязательные `author`, `title`, необязательные `id`, `content_type`; без заданной книги строки URL сопоставляются со всем переданным каталогом.

## Тесты

```powershell
.\.venv\Scripts\python.exe -B -m pytest -q -rs -p no:cacheprovider --basetemp=.pytest-tmp tests
```

Набор включает **396 тестов**: нормализацию и экспорт Excel, HTML/PDF, принадлежность контента, видимость, идентичность произведения, браузерные сценарии и воспроизведение примера. Все данные локальные; HTTP-запросы в демонстрации запрещены, браузерные ответы перехватываются фикстурами.

Для полного набора без пропусков нужны **Python 3.12+**, `requirements-browser.txt` и доступный Chromium/Edge. Без необязательных браузерных зависимостей соответствующие проверки пропускаются с указанием причины. Тест аудита записывает игнорируемый `tests/audit/observations.json`; это генерируемый диагностический файл.

Workflow [`.github/workflows/tests.yml`](.github/workflows/tests.yml) настроен на `push` и `pull_request`: Ubuntu, Python 3.12, установка только `requirements.txt` и запуск офлайн-тестов. Playwright и Chromium не устанавливаются; браузерные сценарии пропускаются. Схема запуска соответствует [документации GitHub Actions](https://docs.github.com/en/actions/tutorials/build-and-test-code/python). **На GitHub workflow ещё не запускался; успешный CI пока не подтверждён.**

Справка по интерфейсам:

```powershell
.\.venv\Scripts\python.exe -B part1.py --help
.\.venv\Scripts\python.exe -B part2.py --help
.\.venv\Scripts\python.exe -B examples/run_demo.py --help
```

## Ограничения и назначение прототипа

- Проект демонстрирует правила извлечения, сопоставления и объяснения решений. Точность на произвольных сайтах не измерялась; 396 тестов не заменяют такую оценку.
- Нет OCR, авторизации, решения CAPTCHA и проверки полноты или фактической выдачи скачиваемого файла. Chromium не нажимает download-ссылки и блокирует загрузки книг и медиа.
- Принадлежность контента определяется ограниченными эвристиками. Нестандартная разметка, неявное авторство и противоречивые доказательства могут оставить статус 2.
- Для PDF сверяются начало документа и метаданные. Явная рецензия не считается текстом произведения; неозаглавленную рецензию без признаков роли алгоритм универсально не распознаёт.
- HTTP-загрузка ограничена таймаутами, размером HTML до 5 MiB и четырьмя редиректами; автоматических повторов нет. Сетевой PDF читается диапазонами с бюджетом 512 KiB и анализом первых трёх страниц. Если сервер или документ не позволяет извлечь достаточно данных, результат может быть 2.
- Сетевые результаты отражают состояние страницы в момент проверки. Полные страницы и тексты книг в результаты не экспортируются; остаются метаданные, короткий фрагмент и доказательства.
- Очередь, база данных и распределённые воркеры описаны как [план масштабирования](docs/scaling.md), а не как возможности текущей реализации.

Правила интерпретации доказательств и контрольные пары описаны в [инвариантах](docs/invariants.md).

## Структура репозитория

```text
book-content-monitor/
├── part1.py                  # нормализация и дедупликация Excel
├── part2.py                  # каталог, решения, CLI и экспорт
├── pages.py                  # HTTP, HTML/PDF и локальные признаки
├── browser.py                # Playwright и computed styles
├── requirements*.txt         # базовые и браузерные зависимости
├── examples/
│   ├── synthetic_input.xlsx  # 18 записей и 7 сценариев
│   ├── run_demo.py           # офлайн-запуск существующих CLI
│   ├── fixtures/             # 4 HTML и 3 синтетических PDF
│   └── output/               # 3 сохранённых результата HTTP-only
├── tests/                    # тесты, фикстуры, аудит и регрессии
└── docs/                     # инварианты и план масштабирования
```

`.gitignore` исключает окружения, секреты, кэши, логи и результаты локальных запусков. Для трёх проверенных учебных файлов в `examples/output/` оставлены явные исключения.
