# Правила принятия решений

Классификатор проверяет признаки размещения ожидаемой книги по доступному документу. Он сохраняет причины, доказательства и неопределённость, чтобы решение можно было проверить вручную. Значения статусов описаны в [README](../README.md).

## Идентичность произведения

Для положительного решения нужны убедительные признаки совпадения названия и автора. Имя человека в отзыве, профиле или подписи к публикации не заменяет автора книги. Существенный конфликт между основной карточкой и метаданными требует неопределённого результата.

Номера томов сравниваются по смысловому значению: например, `13`, `013` и `XIII` могут обозначать один том. Разные номера томов не подтверждают одно произведение. Такое сравнение не объединяет исходные записи и не переписывает их идентификаторы: `book_id` строится по нормализованной идентичности записи. Различия `е/ё` сохраняются в ключах идентичности.

## Принадлежность доказательств

Для статуса `1` недостаточно найти на странице название и любую ссылку EPUB. Файл, текст для чтения или аудиоконтент должны относиться к той же книге. Нельзя объединять автора из одной карточки, название из другой и ссылку из рекомендаций.

Самостоятельные карточки сохраняют свои границы. Реклама, отзывы, рекомендации и библиографические упоминания не становятся основной книгой только из-за соседства в DOM. В то же время принадлежащий книге файл не считается рекламой лишь потому, что находится внутри `aside`.

Аудиоверсия того же произведения учитывается как признак размещения. Наблюдаемый формат, формат каталога и их различие сохраняются отдельно.

## HTML, PDF и браузер

HTML анализируется с учётом локальных областей, метаданных и видимости. Если HTTP показывает признаки незавершённой динамической страницы, режим `auto` может подключить Chromium и дождаться содержимого в пределах таймаута. Загрузочная оболочка, которая не раскрылась, не подтверждает отсутствие книги.

У PDF анализируются метаданные и доступный текст. Упоминание книги внутри чужого документа не делает весь PDF её текстом. Роль рецензии, пересказа или учебного материала учитывается отдельно; собственный текст такого документа не является автоматическим доказательством размещения произведения.

Тип ответа определяется по содержимому и MIME: суффикс `.pdf` сам по себе не исключает HTML и JavaScript. Полнота PDF и книги не устанавливается по одной кнопке скачивания или ограниченному фрагменту текста.

## Неполные данные

Сетевые ошибки, защита сайта, существенные противоречия и недостаточное обследование требуют явной причины и могут приводить к статусу `2`. Неполный документ отмечается `partial`; отсутствие признаков в его фрагменте не даёт уверенного отрицательного вывода. При этом надёжное собственное положительное доказательство не отменяется только из-за неполноты остального документа.

Посторонний неполный блок не должен аннулировать подтверждённое размещение целевой книги. Ошибка одного браузерного обследования не останавливает обработку следующих URL.

## Проверяемые результаты

| Ситуация | Решение в предусмотренном синтетическом сценарии |
|---|---|
| Собственная карточка, совпавшие автор и название, связанный EPUB | `1 / placement_signs` |
| Карточка другой книги | `0 / no_match` |
| Неизменившаяся загрузочная оболочка | `2`, с причиной незавершённой загрузки |
| Собственный текстовый PDF | `1 / placement_signs` |
| PDF другой книги | `0 / different_pdf_book` |
| Демонстрационная PDF-рецензия | `2 / pdf_document_role_unresolved` |
| Динамическая карточка после успешного выполнения JavaScript | `1 / placement_signs` |

Эти примеры воспроизведены офлайн; точные результаты и команды приведены в [README](../README.md). Статус `1` обозначает обоснованные признаки размещения и не является правовой оценкой или доказательством полноты файла.
